# Privileged gateway socket adapter

2026-10-16. Synthetic, local HTTP-upgrade wire evidence; this is not a real Hermes, proxy-service, TLS deployment, Windows, or packaged Electron qualification.

`packages/platform/socket-transport.ts` implements the existing `GatewaySocket` interface with the approved `ws@8.22.0` dependency and `@types/ws@8.18.2`. It uses no handwritten WebSocket framing implementation. The transport remains privileged; plans contain dashboard credentials or provider tickets and never belong in renderer IPC, logs, or exception causes.

The adapter copies configured headers, rejects framing/cookie header injection, uses the exact plan URL, refuses redirects, and has no cookie jar. TLS certificate verification stays enabled. Provider plans require the gateway protocol plus a ticket protocol, with the monotonic ticket deadline checked immediately before the single connection attempt. The selected application protocol must be `hermes-gateway-v1`; selecting the ticket is rejected. Dashboard plans offer and accept no protocol. Duplicate critical handshake headers and any extension response are rejected. `ws` verifies the server nonce response and handles client random keys/masking, frame validation, fragmentation, UTF-8, and close/control frames. Automatic compression and automatic pongs are disabled; bounded pong writes use the same accounting as other writes.

Limits and lifecycle:

- Maximum received message and outgoing text: 4 MiB. `ws` checks declared frame/message size before collecting the payload. Its fragment count and buffered-chunk count limits are each 4,096. Binary messages are rejected.
- Pending outgoing data plus frame overhead is limited to 4 MiB + 14 bytes and 1,024 writes. The adapter also checks `ws.bufferedAmount`. It fails closed instead of queuing unlimited data. Every outgoing queue has a 20-second drain deadline.
- Opening has a 20-second absolute timer as well as the library handshake timeout. Aborting immediately retires and terminates the socket.
- Every 30 seconds the client sends a random ping and requires its exact pong within 20 seconds. This detects disconnected or stalled peers, including peers withholding an incomplete frame. A peer continuing to answer pings can keep a fragmented message incomplete; memory and fragment counts remain bounded, and gateway RPC/startup deadlines independently retire unfinished requests. The adapter does not inspect private `ws` parser state or promise an absolute per-message completion deadline.
- Local close retires callbacks immediately, requests a normal close handshake, and terminates after one second if the peer does not finish. The close callback is delivered once across failures, aborts, peer disconnect, and repeated close calls. Public failures expose only `Socket unavailable`.

Validation: `node --experimental-strip-types --test tests/socket-transport.test.mjs` passed 37 tests/subtests; `node_modules/.bin/tsc -p config/tsconfig.core.json` passed. Tests use actual loopback HTTP upgrade servers and raw frames, with mocked clocks only for the handshake and heartbeat deadlines. They cover same-origin proxy/header forwarding, no cookies across connections, fresh handshake keys, masked writes and pongs, fragmented Unicode, incremental extended frame headers, close echo, failed/duplicate/extended handshakes, wrong/missing provider protocols, HTTP rejection and redirects, excessive declared length before payload, aggregate payload and fragment-count limits, invalid UTF-8, binary frames, masked server frames, RSV/opcode/control violations, cancellation, disconnect, queue pressure, and exactly-once retirement. The stalled-write timer is present but has not been timing-qualified against a real congested network.

Omitted features are deliberate: compression/extensions, binary messages, redirect following, cookie persistence, automatic reconnection, HTTP CONNECT proxy discovery, and application-level replay. Configured reverse-proxy authorization headers are supported. Credential storage, owner/generation fencing, ticket minting, RPC semantics, and reconnect policy remain with their existing owners. Live Hermes and physical-platform checks are still required before claiming end-to-end compatibility.
